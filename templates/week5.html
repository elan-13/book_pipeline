2 — Idempotency

An idempotent pipeline produces the same output regardless of how many times it is run with the same input. Click the button multiple times — the result never changes.

Idempotency Demo

Each run computes a deterministic SHA-256 checksum of the output. Identical checksums confirm idempotency.

Click "Run Pipeline Again" to simulate repeated runs
Idempotency Strategies
Upsert / MERGE

Insert new rows; update existing rows by primary key. Prevents duplicates on re-runs.

Partition Overwrite

Drop and reload a specific time partition. Re-runnable without duplicating data across partitions.

Checksum Deduplication

Hash each row; skip rows with matching checksums already in the target table.

4 — Error Handling, Retry & Backfill

Production pipelines must gracefully handle transient failures with exponential back-off retries and support backfill for missed historical partitions.

Retry Pattern (Python)
Python import time, logging def with_retry(fn, max_retries=3, backoff=5): """Exponential back-off retry decorator.""" for attempt in range(max_retries): try: return fn() except Exception as e: wait = backoff * (2 ** attempt) logging.warning( f"Attempt {attempt+1} failed: {e}. " f"Retrying in {wait}s..." ) time.sleep(wait) raise RuntimeError("Max retries exceeded")
Error Handling Strategies
Dead Letter Queue

Failed records are routed to a DLQ for inspection and manual reprocessing without blocking the main pipeline.

Exponential Back-off

Retry delays double on each failure (5s 10s 20s) to avoid thundering-herd on transient network issues.

Partition Backfill

Re-run pipeline for a specific date range (Airflow catchup=True) to recover missed data partitions.

Resilience Design Principles
IdempotencyRe-running the same pipeline always produces the same output — no duplicate data
AtomicityAll pipeline steps succeed together or all roll back — no partial writes to the warehouse
Retry LogicTransient failures (network, API timeout) are retried with exponential back-off up to 3x
Dead Letter QueueUnrecoverable records are isolated in a DLQ for manual inspection without blocking the pipeline
Backfill / CatchupMissed historical partitions can be reprocessed on-demand using Airflow's catchup mechanism
Schema EvolutionBackward-compatible schema changes (add columns, nullable fields) handled without pipeline restarts
ObservabilityStructured logging, metrics (latency, throughput, error rate), and alerting integrated into every stage
